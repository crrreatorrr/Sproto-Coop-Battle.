# Base payload and optional boss media

The public inventory and build manifest continue to include **every** public file, byte and hash. `publicBytes` and runtime `staticBytes` remain the honest totals. The existing **10 MiB** gate applies to `basePublicBytes` / runtime `baseStaticBytes`: the total minus only valid registered transformation, action and dedicated FX page files. Title remains capped at **1.5 MiB**, first stage at **3 MiB** and critical requests at **30**. First-stage accounting still includes the first warmed transformation page and its request. Optional classification does not remove a file from loader groups or reduce request counts.

Optional media has a separate explicit **64 MiB encoded-file total** and **1 MiB encoded per-page cap**. This is a classification by complete runtime-valid registration, not a directory exemption. A file qualifies only through a real manifest boss, valid phase and recognized renderer action (or an eight-second transformation), with an exact canonical path under `assets/bosses/actions/` or `assets/bosses/transformations/`. Dedicated FX may also qualify under `assets/bosses/effects/`, with a lowercase canonical `.png` or `.webp` path and one of the eight actual renderer purposes: `lane`, `spread`, `homing`, `impact`, `signature`, `special`, `hurt`, `death`. Existing runtime planners validate timing, anchors/core rectangles, page grids and explicit cell indices. Actual image dimensions must match the complete page. Texture sides stay at most2048pixels, decoded pages at most8MiB.

FX uses the actual `CoopSpriteTimeline` planner with the renderer's native96×96 cell, full96×96 core, anchor inside the cell, positive safe frame ticks, at most64frames, complete page-grid dimensions and runtime source rules. Only selector-owned phase indices0/1 can classify dedicated FX or reserve scratch, even if a manifest declares additional phases. Unreachable metadata still contributes all loader-retained bank bytes/residency. Every page of a qualifying clip must pass actual file existence/dimensions, encoded/decoded limits and source validation before any dedicated page is classified optional. Mixed clips may use legacy and dedicated paths; full validation applies to all pages, and only canonical dedicated FX pages become optional. Original manifest fallback body/projectile paths always remain base. Existing Zephyr/Rune registered effects continue using their legacy projectile paths and remain base without a classification/hash/budget change.

Aliases, traversal, URL queries, incorrect namespaces, missing/malformed pages and unknown boss/phase/action/FX-purpose registrations fail diagnostics. Every page in an invalid clip stays base unless a separate complete valid clip uses that exact file. Unregistered files in the reserved namespaces also remain base and fail diagnostics. Shared valid pages count once, by exact public path. Legacy-only malformed FX retains its existing renderer fallback and classification; it does not acquire an optional exemption. Original projectile/actor fallback banks remain base media; an FX directory alone grants no exemption. No file is omitted from total inventory or hashes.

The **32 MiB retained boss-presentation envelope** includes the actual fallback body/FX banks in every legal overlap. The resource model checks:

- Normal current/next-boss fallback prefetch, including every FX page in both phases of each retained boss.
- Transformation current/next pages plus one held full cel and every current-boss fallback/FX bank from both phases.
- Phase-one action current/next pages plus the first transformation standby page, held action cel and every current fallback/FX bank.
- Phase-two action current/next pages plus held action cel and every current fallback/FX bank; transformation pages have been released.

Every scene also reserves `fxScratchDecodedBytes`: the global maximum native cell RGBA size among valid registered FX plans. The renderer retains one reusable scratch rather than a cache per effect/frame. Current valid FX cells are96×96, so this adds36,864bytes once, conservatively even in a scene before an FX event has drawn. Invalid FX plans keep their existing legacy fallback and do not increase this reserve. The same runtime path, geometry, anchor, full-core,64frame and page resource checks determine eligibility. The scratch is additional decoded residency, not a reduction in bank residency.

Transformation/action streams retain at most two distinct pages each. FX is **not** a two-page stream or an event-only cache: the current loader retains all declared FX bank pages from both phases for the stage lifetime, regardless of optional byte classification, validity or whether an event has drawn. Ordinary prefetch also includes all next-boss FX banks; active T/action pins release that next-boss prefetch as the loader already does. The budget model counts these exact legal overlaps and deduplicates shared files by identity. Looping walk/charge-rush clips include the last-to-first page pair. The runtime already releases actions during transformation and clears old held cels on state/phase changes; this policy adds build-time validation, without changing loading or rendering behavior.

The first boss currently uses all30critical requests. Adding a separate dedicated first-boss FX bank would be request31 and fails that unchanged gate, even if its bytes qualify as optional and fit the64MiB/32MiB limits. Bront FX therefore uses the existing projectile bank for the interim integration. Future dedicated registrations still require a concrete request/first-stage budget review; this policy does not authorize new art, paths, clip registrations or loader changes.

This envelope is specifically retained boss presentation. Persistent selected fighters, scenery, shadows, UFO and other loader groups must be reported separately in actual integration measurements; the32MiBfigure is not a claim about total browser heap, total image residency, GPU allocation or when the browser collects released images.

`scripts/streamed-media-budget.mjs` analyzes the same registrations and actual file dimensions as the loader/runtime planners. Inventory, exact fixture and built manifest report total/base/optional bytes, optional path/hash identities and the maximum legal presentation overlap. No budget cap is silently changed by refreshing the fixture. `tests/streamed-media-budget.test.js` exercises malformed and aliased registrations, unregistered files, complete-grid geometry, shared/mixed pages, encoded/decoded boundaries, all-phase FX residency and fallback/standby/held-cel/scratch overlap overflows. It uses the real `AssetLoader.groups` and first-stage budget calculation to prove that optional FX still adds its stage request and bytes. New actor/FX art still requires independent visual, source and real-renderer QA before registration.
